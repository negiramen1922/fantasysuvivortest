## 2. アーキテクチャ

### ゲームループ

```
frame(t)                    ← requestAnimationFrame
 ├ state==='playing'  → update(dt)
 ├ state==='levelup'  → stepFx(dt)
 ├ state==='chest'    → stepFx(dt) + chestAnim(dt)
 ├ render()
 └ perfTick(dt)
```

`dt` は `Math.min(0.05, 経過秒)` でクランプ。タブ復帰時の巨大 dt を防ぐ。

### state（文字列）

`'title'` / `'playing'` / `'levelup'` / `'paused'` / `'chest'` / `'test'` / `'dead'`

`'playing'` 以外では `update()` が走らないので世界が止まる。演出だけ進めたい状態は
個別に `stepFx(dt)` を呼んでいる。

### update() の実行順（重要）

```
movePlayer → 回復 → aim → runWeapons → moveEnemies
 → 各種 move*(dt) （飛翔体・設置物）
 → moveGems / movePickups → sweepDead
 → spawn → checkBoss → moveEbul → stepFx → syncHud
```

`sweepDead()` の位置を変えないこと（後述）。

### 座標系

ワールド座標は無限平面。カメラは常にプレイヤー中心。
`render()` 冒頭で `ctx.setTransform(DPR,0,0,DPR,0,0)` → `ctx.translate(-camx,-camy)`。
画面サイズ `W/H` は CSS px、`DPR` は最大2で clamp。`resize()` が両方を更新する。

### 描画順（後ろ→前）

地面 → ゾーン → ブラックホール → 敵 → 岩 → 飛翔体 → 敵弾 → レーザー → 粒子 →
自機 → チャクラム → ベル → 剣 → 鎌 → 爆弾 → 焔輪 → fx各種 → 連鎖 →
**敵の輪郭** → ダメージ数字

敵は早い段階で描かれてエフェクトに埋もれるため、最前面で `drawEnemyOutlines()` が
輪郭だけを重ねている。これがないと最大構成で敵が1体も見えなくなる。

## 4. 実装上の必須ルール

**この章が最重要。過去に実際に事故った内容。**

### 4-1. 敵の削除は遅延方式（絶対に戻さないこと）

`kill()` は `e.dead=1` を立てるだけで配列から抜かない。実際の削除はフレーム末の
`sweepDead()` が一括で行う。

理由：判定ループは `for(j=enemies.length-1;j>=0;j--)` の形が11箇所ある。
`hurt()` の中で元素反応（`boom` / `spread`）が起きると**1回のダメージで複数の敵が
同時に死ぬ**。即時 splice すると `enemies.length` が `j` を下回り、
`enemies[j]` が undefined になって `Cannot read properties of undefined (reading 'x')`
で停止する。実際にこのクラッシュが発生した。

- 全ての敵ループで `if(e.dead) continue;` を必ず入れる
- 索敵（`nearest` 等）も dead を除外する
- `sweepDead()` を update の途中から動かさない

### 4-2. 大きな文字列置換で関数を消さないこと

これまで `strike` / `sweepDead` / `moveBombs` / 拾い物の描画関数などを、範囲指定の
置換に巻き込んで**5回消失させている**。しかも呼び出し側は残るので、
その武器を取った瞬間にクラッシュする形で表面化する。

**編集後は必ず以下を実行すること。**

```bash
# JSを抽出して構文チェック
python3 -c "
import re;s=open('index.html',encoding='utf-8').read()
open('/tmp/check.js','w',encoding='utf-8').write(re.search(r'<script>(.*?)</script>',s,re.S).group(1))"
node --check /tmp/check.js

# 未定義・重複の検出
python3 - <<'EOF'
import re
js=open('/tmp/check.js',encoding='utf-8').read()
defined=set(re.findall(r'\bfunction (\w+)\(', js))
called=set(re.findall(r'(?<![\w.\'"])([a-zA-Z_]\w*)\s*\(', js))
skip={'if','for','while','switch','catch','function','return','typeof','JSON','Math',
 'Object','Array','String','Number','parseInt','parseFloat','setTimeout','clearTimeout',
 'addEventListener','requestAnimationFrame','console','var','new','onHit','cv','ctx',
 'document','window','localStorage','performance','isNaN','Boolean','in'}
print("未定義:", sorted(c for c in called if c not in defined and c not in skip and c[0].islower()) or "なし")
print("重複:", [f for f in defined if len(re.findall(r'^function '+f+r'\(',js,re.M))>1] or "なし")
EOF
```

「重複」の検出も必須。武器関数を書き直したとき**旧定義が残って後勝ちで上書きされ、
新しい実装が全て無視される**事故が起きた（8関数が同時に重複していた）。

### 4-3. 発生源の追跡（SRC）

会心率と元素付与率は武器ごとに違うため、ダメージを出している武器IDをグローバル
`SRC` に入れてから `hurt()` を呼ぶ。飛翔体は `moveShots` 側で `SRC=s.src` を設定する。

- 必ず `SRC=null` に戻す
- `react()` は `SRC` を退避してから null にする（反応ダメージは武器の会心を継がない）

### 4-4. パフォーマンスの上限は「判定数 × 敵数」

判定オブジェクトは毎フレーム全敵を走査する。負荷はこの積で決まる。

実測（Android Chrome）: 判定1,763 × 敵300 = 積529千/フレーム → **60fps維持**

- 判定数と敵数は逆相関する（敵が多いと飛翔体が貫通を使い切って早く消える）ため、
  理論上の最悪ケースには到達しない
- 空間グリッドは**現時点で不要**。必要になったら `Math.hypot` →
  `Math.sqrt(dx*dx+dy*dy)` の置換を先に試すこと（2〜4倍速い）

**オブジェクト数に直結する軸には必ず上限を設けること。**
限界突破で「数」を上限なしにすると確実にフレームが落ちる。

### 4-5. 発動間隔の絶対下限

`ready()` に `Math.max(0.12, cd*cdr())` の下限がある。これがないと基礎CDの短い武器
（チェンソー0.20秒、焔輪0.30秒）が限界突破で毎秒16回以上発動し、単独で全体負荷の
24%を占めた。

### 4-6. 元素反応のレート制限

- 全体：毎秒14回まで（`rtok`）
- 敵ごと：0.55秒のクールダウン（`e.rcd`）
- 連鎖の深さ：2段まで（`rdep`）

聖光系の広範囲武器は毎秒3回×全敵を叩くため、制限がないと1フレームで数千回の反応が
発生する。**緩めるときは必ず負荷を測ること。**

### 4-7. localStorage

セーブは `bsv_save` キー1つに集約。`try/catch` で囲んであり、使えない環境
（サンドボックス等）ではセッション内のみで動作する。この構造を維持すること。

### 元素反応（5属性・10組）

|  | 炎 | 氷 | 雷 | 光 | 闇 |
|---|---|---|---|---|---|
| **炎** | — | 融解 | 過負荷 | 拡散 | 炎症 |
| **氷** | 融解 | — | 超電導 | 拡散 | 凍結 |
| **雷** | 過負荷 | 超電導 | — | 拡散 | 感電 |
| **光** | 拡散 | 拡散 | 拡散 | — | 消滅 |
| **闇** | 炎症 | 凍結 | 感電 | 消滅 | — |

- **過負荷** 半径115の爆発 / **融解** 単体特大 / **超電導** 範囲＋鈍足3.2秒
- **拡散** 元素を周囲10体へ伝播 / **炎症** 5秒の継続ダメージ
- **凍結** 完全停止1.2秒×(1−抵抗) / **感電** 本体＋周囲4体に継続ダメージ
- **消滅** `min(最大HPの1%, 元ダメ×5)`。雑魚には無意味、ボスに刺さる設計

土属性（グランドアッパー、ロックボール）は**反応を持たない**。物理的な圧が個性なので
意図的にそうしている。会心型として扱う。

### 最大構成の確認

テストモード（画面右上の⚙ボタン、または `T` キー）で:

1. `全武器 Lv10` → `限界突破+10` を2回 → `無敵 ON`

約9秒で上限まで溜まる。最悪ケースの再現に使う。

## 8. 設計上の判断メモ

後から「なぜこうなっているのか」で迷わないための記録。

- **合成進化（雷迅斬）は削除済み。** 大剣Lv10の到達点が覚醒「飛翔斬撃」と衝突したため。
  進化を1種だけ残すのは例外の暗記でしかないと判断した
- **会心は武器の軸ではなくキャラのステータス。** 元素側（元素親和・元素熟知）が既に
  キャラのステータスだったので、物理だけ武器軸なのは非対称だった
- **土と闇は最初は反応なしだった。** 闇だけ後から「濃縮」として反応を追加。
  役割（範囲爆発/単体特大/移動阻害/伝播/継続ダメージ）で数えると6つしかなく、
  属性を増やすより空いている役割を埋める方が正しいと判断した
- **一括吸収アイテム（磁石）はフィールドに湧く。** 宝箱に入れると自動発動になり、
  「いつ拾うか」という位置取りの判断が消えるため
- **画面揺れは設定で切れる。** 最大構成で揺れ続けて酔うという指摘があった。
  根本的には「揺れは大きな出来事だけ」にすべきだが、まず選べるようにした
