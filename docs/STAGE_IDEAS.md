## 決定済みのロードマップ

| # | 舞台 | 属性テーマ | 盤面ルールの主題 |
|---|---|---|---|
| ⑤ | **氷系（氷河・凍土）** | 氷 | **移動**（慣性・滑る） |
| ⑥ | **砂漠** | 土 | **視界と射程**（砂嵐・地中） |
| ⑦ | **炎（火山）** | 炎 | **床**（溶岩＝立ち位置） |
| ⑧ | **工場（機械都市）** | 雷 | **時間**（周期で動くハザード） |
| ⑨ | **魔界** | 闇 | **情報**（暗闇・呪い） |
| ⑩ | **宇宙** | 無属性／全部 | **物理法則**（無重力・重力井戸） |

移動 → 視界 → 床 → 時間 → 情報 → 物理法則、と「プレイヤーが奪われるもの」が段階的に重くなる並び。属性も 氷→土→炎→雷→闇→無 で散っているので、耐性設計（特定属性ビルドへのカウンター）を各ステージに1つずつ置ける。

### 1-4. 既知の穴（新ステージを作る前に把握しておくこと）

1. **BGM がステージ③④に無い。** `TRACKS` は `home/s1/s1b/s2/s2b` の5曲だけ。`playBGM('s3')` は `TRACKS['s3']` が無いので**無音**になる。⑤〜⑩を足すと無音ステージが8個になる。**先に `s3/s3b/s4/s4b` を埋め、以後は新ステージと同時に2曲作る運用にする。**
2. **無限ランがステージ①〜③しか回らない。** `endlessTick` / `checkBossEndless` が `(blk%3)+1`。④が既に循環に入っていない。**ステージ数連動（`%STAGE_COUNT`）に直すのが先**。⑩まで作ると1周50分になるので、無限ランの舞台は「解放済みステージのみ」等の選別も要検討。
3. **ステージ③の一部ザコが仮絵。** `drawS1Shape` 冒頭の `S3A` テーブルで lich/necro/dullahan/boomer/gargoyle/fly をゴブリン等に置換している。④（海）は `drawOceanShape` で全て手続き描画・PNG無し。**新ステージは「手続き描画で完結させる」のが既定路線**（PNG は後追いで差し替え可）。
4. **地面が色違いのグリッドだけ。** `drawGround` は `curGround.{bg,grid,dot}` の格子＋点のみ。**地形・障害物・見た目の個性は未実装**＝⑤以降の主戦場。ベルトコンベア（⑧）・星（⑩）などは `drawGround` にステージ別の描画フックを足す形になる。
5. **レベルの受け皿。** 武器スロット6・パッシブ6のまま。HANDOFF §6 の「Lv67で強化先が尽きる」は未解消。**⑤〜⑩で解放Lvを上げ続けるなら、スロット拡張か限界突破の軸追加が必須**（→ §6 未決事項）。
6. **ステージ選択UIが縦に伸びる。** 10ステージ並ぶ前提の設計になっていない（`renderStageSelect`）。

## 2. 設計の考え方

既存4ステージが担っている「圧のかけ方」を並べると、空きが見える。

| 圧の種類 | ①〜④ | ⑤〜⑩ で埋める |
|---|---|---|
| 数で押す／速度で詰める／硬さ／遠距離 | 済（②③④で網羅） | ベースとして継続 |
| 支援・強化する敵 | ③のみ | ⑧（修理ドローン）で再登場 |
| **移動そのものの妨害** | なし | **⑤ 氷（慣性）／⑥ 蟻地獄／⑩ 無重力** |
| **視界・情報の制限** | なし | **⑥ 砂嵐／⑨ 暗闇** |
| **地形／環境ダメージ** | ④の澱みのみ | **⑦ 溶岩／⑧ プレス・レーザー** |
| **時間で変化する盤面** | なし | **⑧ 周期ハザード／⑩ 重力井戸の移動** |
| **属性耐性によるビルド強制** | なし | **各ステージに1つずつ**（⑤氷耐性・⑦炎耐性・⑧雷耐性…） |

**⑤以降は「敵の種類」ではなく「盤面のルール」で差を付ける。** ザコ差し替えだけのステージは②③④で3回やっているので、それだけだと飽きが来る。

**属性耐性の設計指針**：そのステージの属性を**半減**にする（例：火山＝炎ダメージ0.5倍）。ただし**完全無効にはしない**。ビルドを崩されるのは面白いが、詰みは面白くない。`ETYPE` に `eres:{fire:0.5}` のようなフィールドを新設し、`hurt()` の属性乗算に1行足すのが最小実装。

## 3. ステージ案（⑤〜⑩）

各案：**コンセプト → 地面色 → 固有ギミック → ザコ10種 → ボス4体 → 解放条件 → 報酬 → 実装コスト**。
実装コストは既存資産の流用度から見た相対評価（★1＝ロスター差し替えのみ／★3＝新システムが要る）。

---

### ⑤ 凍てつく氷河（氷系）

- **一言**：思い通りに止まれない。**移動が資源になる**最初のステージ。
- **地面**：`bg:'#0a1622' grid:'rgba(120,200,235,.24)' dot:'rgba(200,240,255,.14)'`
- **固有ギミック**
  1. **氷結床**：`movePlayer` の減速率を下げて慣性を持たせる。**全面ではなく帯状／円形のパッチ**で置く（全面だと理不尽になり、パッチなら「避ける／使う」判断が生まれる）。実装は `puddles` と同型の配列＋`movePlayer` の1分岐。
  2. **ブリザード**：90秒ごとに30秒間、画面が白く霞んで（`nmTint` と同じ全画面フィルタ）一定方向へ風が押す。視界＝敵の発見が遅れる。
  3. **雪崩**：`umibozuTick` の壁ロジックを流用。画面の一辺から雪の壁が横断し、当たると大ダメージ＋押し流される（避けゲー的な間）。
  4. **氷耐性**：氷属性ダメージ半減。凍結（完全停止）が効きにくい敵が多い＝**氷ビルドへのカウンター**。
- **ザコ案**：氷狼（速い・群れ）／雪男（重量級）／アイスゴーレム（被弾で氷片を飛ばす）／氷柱（設置・接近で射出＝`shoot` の据置版）／スノーワーム（`burrow`）／フロストウィスプ（`fly`・命中で鈍足付与）／雪だるま（撃破で2体に分裂＝スライム系流用）／氷の弓兵（`shoot`）／セイウチ（`charge`）／吹雪の精（スウォーム＝`swarmK`）
- **ボス案**：①白銀の熊（`charge`）→ ②氷竜（扇状ブレス＝`beam` 改）→ ③雪の女王（`summon`＋全域鈍足フィールド）→ ④**氷河の巨人**（`last`・`slam` で地面を割り、氷結床を増やす）
- **解放**：④クリア（§6 の方針転換案を採るなら「クリア」ベース。従来式なら ④で Lv70）
- **報酬**：武器「氷嵐槍／アイスシールド（設置型）」／キャラ「氷の狩人」（既存 `cryo` があるので、キャラは無しでも可）
- **実装コスト**：★★☆　慣性は `movePlayer` 1箇所、雪崩は海坊主流用、吹雪は画面フィルタ。**新システムの割に軽い＝⑤に置くのは妥当**。

### ⑥ 灼砂の遺跡（砂漠）

- **一言**：**見えない・届かない**。足元から来る。
- **地面**：`bg:'#1d1608' grid:'rgba(210,180,90,.22)' dot:'rgba(255,230,150,.14)'`
- **固有ギミック**
  1. **砂嵐**：定期的に視界が落ち、**飛翔体の射程が一時的に短縮**（`RNG()` に環境係数を掛ける）。遠距離ビルドへの明確なカウンター。近接・追尾武器の相対価値が上がる。
  2. **蟻地獄**：すり鉢状の吸引点が盤面に数箇所（`moveVacs` の引き寄せを符号反転してプレイヤーに適用）。中心に落ちると継続ダメージ。**逃げ道の形を歪める**。
  3. **`burrow` 主体のロスター**：足元から湧く敵が多く、「背後から来る」前提が崩れる。予告は地面のひび割れ（`drawTele`）。
  4. **土耐性**：物理・土系のノックバックが効きにくい（砂に沈む）。
- **ザコ案**：サンドワーム（`burrow`・大型）／スカラベ（群れ・`swarmK`）／砂のミイラ（③流用）／ハイエナ（速い・side dash）／砂蠍（毒＝`applyPois` 流用）／砂像の衛兵（正面盾＝③`shieldman` 流用）／ジン（`fly`＋短距離テレポート）／干からびた木（設置・砂煙で視界を奪う）／砂スライム（分裂）／禿鷲（`fly`・上空から急降下）
- **ボス案**：①巨大蠍（挟み込み＋毒）→ ②砂の王ミイラ（`summon`）→ ③アントライオン（画面全体の吸引フェーズ）→ ④**スフィンクス**（`last`・一定時間ごとに「特定属性が効かない」ルールを宣言＝謎かけ）
- **報酬**：武器「砂塵の刃／ミイラ包帯（拘束）」／キャラ「盗賊」（宝箱・銀貨系の成長）
- **実装コスト**：★★☆　射程短縮は既存の `RNG()` に1係数、吸引は `moveVacs` 流用。

### ⑦ 灼熱の火口（炎）

- **一言**：**立ち位置が命取り**。敵より床が怖い。
- **地面**：`bg:'#1a0b08' grid:'rgba(180,70,30,.26)' dot:'rgba(255,140,60,.16)'`
- **固有ギミック**
  1. **溶岩溜まり**：`trails`/`puddles` と同型の新配列。警告リング → 噴出 → 30秒残留。踏むと毎秒ダメージ（`KILLER={k:'lava',nm:'溶岩'}`）。**プレイヤーだけに効く**（敵は平気＝逃げ場が減る形の圧）。
  2. **噴火**：1〜2分おきに全域へランダムな着弾予告 → 落石ダメージ＋着弾点が溶岩化。時間が経つほど安全地帯が減る。
  3. **炎耐性**：炎属性半減。融解・過負荷の旨味が落ちる＝**炎ビルドへのカウンター**。氷・雷ビルドが輝く。
- **ザコ案**：火トカゲ（`charge`）／溶岩スライム（死亡時に溶岩を残す）／マグマゴーレム（重装・高`res`）／火の玉（`fly`・自爆）／サラマンダー（`shoot`・火球）／灰の亡霊（スウォーム）／溶岩甲虫（正面装甲）／噴火する石像（設置砲台）／フェニックス雛（撃破後に一度だけ復活）／煤コウモリ（群れ）
- **ボス案**：①炎獄狼（`charge`・通過跡が溶岩）→ ②溶岩巨人（`slam`＋落石弾幕）→ ③双頭のドレイク（`fly`＋`beam`）→ ④**イフリート**（`last`・終盤で全域溶岩化、安全地帯が数個だけ残る）
- **報酬**：武器「溶岩弾／火山槌」／キャラ「炎術士」
- **実装コスト**：★★☆　溶岩は `movePuddles` の複製。**⑤で作った「床ハザード」の枠組みをそのまま再利用できるので、⑤の後だと更に安い**。

### ⑧ 鉄と稲妻の工場（機械都市）

- **一言**：**盤面が時計になる**。周期を覚えれば安全、忘れれば死ぬ。

### ⑩ 星海（宇宙） — 最終ステージ

- **一言**：**物理法則が変わる**。上下左右も、止まることも当てにならない。集大成。
- **地面**：`bg:'#04040c' grid:'rgba(90,90,160,.16)' dot:'rgba(255,255,255,.22)'`（グリッドを薄く、点＝星を強く。`drawGround` に星の瞬きを足すと一気に宇宙になる）

  2. **重力井戸**：盤面をゆっくり移動するブラックホール（既存 `moveHoles` の描画資産あり）。プレイヤー・敵・飛翔体を引き込む。**敵を集める道具としても使える＝プレイヤー有利にも働く両刃**。

## 5. おすすめの進め方

### Step 0：新ステージの前に塞ぐ穴（1〜2回のマージで終わる）
- `endlessTick`/`checkBossEndless` の `%3` → ステージ数連動
- `TRACKS` に `s3/s3b/s4/s4b` を追加（現状③④が無音）
- `STGNUM` に ⑥〜⑩ を追加、`renderStageSelect` を10件想定のレイアウトに
- ステージ解放条件の方針を決める（§6）

### Step 1：⑤氷でギミックの「型」を作る
⑤は **床パッチ（氷）・全画面フィルタ（吹雪）・壁（雪崩）・属性耐性** の4つを一度に入れる。
この4つは⑥〜⑩でそのまま再利用する部品なので、**⑤の実装は「⑤のため」ではなく「⑥以降のインフラ作り」**と考える。
汎用化しておく：

```
STAGES[n].hazard = { patch:{…}, storm:{…}, wall:{…} }   // ステージごとに数値で指定
STAGES[n].eres   = { ice:0.5 }                          // 属性耐性（ETYPE 個別指定も可）
```

### Step 2：⑥砂漠・⑦炎はロスター＋数値替えで作れるようにする
⑤の枠組みが効いていれば、⑥（砂嵐＝storm、蟻地獄＝vac反転）と⑦（溶岩＝patch）は**新規コードがほとんど要らない**。ここでペースが上がる。

### Step 3：⑧工場で「周期ハザード」を新規追加
ベルト・プレスは新しい部品。ここだけは工数を見ておく。

### Step 4：⑨魔界（暗闇）→ ⑩宇宙（集大成）
⑩は⑤〜⑨の部品の再構成＋最終ボス演出に工数を割く。

### 各ステージ共通の進め方
`dev:1` 付きでマージ → `?dev=1` で調整 → 公開（④で実績のある運用）。1ステージあたり：**ザコ10種＋ボス4体＋ギミック1〜2＋BGM2曲＋図鑑テキスト14件**。

## 6. 未決事項（作業前に決めたいこと）

1. **解放条件の方式**（最重要）
   現行は「前ステージで到達Lv」＝20/40/60。この等差で⑩まで伸ばすと Lv200 相当になり、**武器スロット6の受け皿では絶対に届かない**。案：
   - **(a) クリアベースに切り替え**：⑤以降は「前ステージをクリア」。シンプルで詰まらない。**推奨**。
   - (b) Lv要件を緩やかに（⑤70／⑥80／⑦90／⑧100／⑨110／⑩120）＋**スロット拡張（武器8・パッシブ8）を同時実装**。
   - (c) 併用：⑤〜⑦はクリア、⑧以降は「クリア＋到達Lv」。
2. **武器スロット／限界突破の受け皿**：ステージを6つ足すなら避けて通れない。⑤の実装と同時に方針を決める。
3. **属性耐性フィールドの持たせ方**：`STAGES[n].eres`（ステージ一律）か `ETYPE[k].eres`（敵ごと）か。**両方対応し、敵側を優先**が無難。
4. **`hpMul` を使うか**：⑤〜⑩で明示的に難度差を付けるか、これまで通りロスターの強さだけで付けるか。
5. **環境ダメージの対象**：プレイヤーのみ／敵にも効く。前例（海坊主の澱み・ブーマーの毒沼）は**プレイヤーのみ**。氷床とベルトは**敵にも効かせた方が面白い**可能性があるので、ギミックごとに決める。
6. **報酬武器は1ステージ1本でよいか**：現行 `WLOCK` は tornado/briar/railgun/sharkm が各ステージクリア報酬。⑤〜⑩で6本増えると武器41本になる。**武器ではなくキャラやパッシブを報酬にするステージがあってもよい**。
7. **新しい種族タグ**：⑧の「機械」、⑩の「宇宙生物／星獣」を `MTAG` に足すか。足すとナイトメア契約カードの選択肢も増える。
8. **ステージ選択UI**：10件をどう見せるか（横スクロール／2列グリッド／章分け）。
